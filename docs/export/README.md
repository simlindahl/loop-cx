# Local run JSON version 1

`run-v1.schema.json` defines the document shape and explicit units. `sample-v1.json` is synthetic interrupted legacy C2 data, deliberately retaining RPE 3 and absent start-zone/template metadata rather than applying current defaults. `sample-current-v1.json` is a short synthetic test-engine plan with typed final main/splits, HR/zone coverage, source/targets and an observed/effective phase boundary; it is not an official Core dose. Neither sample is a real workout or proof of Android export delivery.

The `run` envelope contains the original frozen phase array, template and HR setup, and exact stored checkpoint. Checkpoint JSON retains its original PascalCase names and TimeSpan constant-format durations; outer export fields use camelCase. The checkpoint's Snapshot owns authoritative total/main/current/completed split values and their known/unknown coverage. Do not recalculate final main from later raw HR. The checkpoint's Plan and Completed describe resolved and actual phases, including runtime changes; OriginalPlan is never replaced by today's factory.

StartContext and PhaseBoundaries are additive checkpoint fields. Missing/null means unknown legacy provenance, not an empty known history. A new empty boundary array means capture is supported but no transition has occurred. EffectiveElapsedMilliseconds is run-relative monotonic time; ObservedElapsedMilliseconds and ObservedUtc are actual callback processing observations. StartAnchorDerivedEffectiveUtc is explicitly start UTC plus effective elapsed, not an observed wall-clock transition. Synthetic acceleration can make effective time later than observed time. Existing run/event elapsed and observed columns retain their meanings.

GPS uses measurement boot nanoseconds and Unix UTC milliseconds; HR uses local GATT-receipt boot ticks (100 ns) and UTC, not a claimed acquisition timestamp. Locations retain SQLite row insertion order as snapshotOrder; this is a storage ordering key, not a sensor-provided ID. Event/HR sequence values retain their existing journal identities. Unknown values remain null. Interrupted last observation is not process-death/end time; no finish-cause taxonomy is invented.

Run `python scripts/parse-run-export.py docs/export/sample-v1.json` for independent reconstruction without app assemblies or current Preferences. Standard schema validation uses the test-only [MIT jsonschema validator](https://pypi.org/project/jsonschema/), pinned separately from app dependencies; it is not shipped in the APK. The independent consumer decodes enum phase kinds and TimeSpan durations into named phases and exact ticks, validates actual/main/split/coverage conservation, and interprets frozen targets/zones without today's defaults. It returns explicit unknowns for unsupported legacy facts and never derives a new final mean from raw data. A consumer must reject unsupported versions/units and malformed current facts rather than guessing.

The Android journal materializes all tables in one explicit transaction, then projects the detached snapshot without writes. No outbox status changes or Health Connect calls occur. Snapshot consistency is a storage transaction, not a fabricated common callback watermark: existing GPS raw insert precedes its derived checkpoint, so a newly stored GPS row may legitimately lead the last checkpoint (including after a crash). Preserve that raw row and the unchanged derived observation separately; never recompute the checkpoint to hide the difference. HR raw and its checkpoint are already atomic. A dedicated DEBUG ranchu emulator can request `loop-export-json-run` with an existing synthetic UUID; the file is saved only in the app's private files directory. The test hook runs the same backend on a worker so ordinary service callbacks can continue during snapshot validation; it captures only the application directory and no Activity. The hook is absent from Release, adds no screen and never creates a run. Target only the coordinated emulator serial. Production Android sharing, first-use permissions, provider retry state and physical WHOOP outcomes remain outside this foundation.
