# Local run JSON versions 1 and 2

Normal newly prepared Core Android share files use `run-v2.schema.json`, including legacy runs whose optional `provenance` is absent or null. `sample-current-v2.json` is synthetic and illustrates explicit per-run point IDs, actual assessment outcomes and drawable predecessor links. These links describe continuity only, not accepted distance or Ghost verification. Version 2 rejects unsupported provenance and forward/cross-run/broken-chain links; it does not infer legacy quality. The explicit v1 diagnostic projector and existing v1 files/consumers retain their original shape. No format chooser is introduced.

`run-v1.schema.json` defines the document shape and explicit units. `sample-v1.json` is synthetic interrupted legacy C2 data, deliberately retaining RPE 3 and absent start-zone/template metadata rather than applying current defaults. `sample-current-v1.json` is a short synthetic test-engine plan with typed final main/splits, HR/zone coverage, source/targets and an observed/effective phase boundary; it is not an official Core dose. Neither sample is a real workout or proof of Android export delivery.

The `run` envelope contains the original frozen phase array, template and HR setup, and exact stored checkpoint. Checkpoint JSON retains its original PascalCase names and TimeSpan constant-format durations; outer export fields use camelCase. The checkpoint's Snapshot owns authoritative total/main/current/completed split values and their known/unknown coverage. Do not recalculate final main from later raw HR. The checkpoint's Plan and Completed describe resolved and actual phases, including runtime changes; OriginalPlan is never replaced by today's factory.

StartContext and PhaseBoundaries are additive checkpoint fields. Missing/null means unknown legacy provenance, not an empty known history. A new empty boundary array means capture is supported but no transition has occurred. EffectiveElapsedMilliseconds is run-relative monotonic time; ObservedElapsedMilliseconds and ObservedUtc are actual callback processing observations. StartAnchorDerivedEffectiveUtc is explicitly start UTC plus effective elapsed, not an observed wall-clock transition. Synthetic acceleration can make effective time later than observed time. Existing run/event elapsed and observed columns retain their meanings.

GPS uses measurement boot nanoseconds and Unix UTC milliseconds; HR uses local GATT-receipt boot ticks (100 ns) and UTC, not a claimed acquisition timestamp. Locations retain SQLite row insertion order as snapshotOrder; this is a storage ordering key, not a sensor-provided ID. Event/HR sequence values retain their existing journal identities. Unknown values remain null. Interrupted last observation is not process-death/end time; no finish-cause taxonomy is invented.

Run `python scripts/parse-run-export.py docs/export/sample-v1.json` for independent reconstruction without app assemblies or current Preferences. Standard schema validation uses the test-only [MIT jsonschema validator](https://pypi.org/project/jsonschema/), pinned separately from app dependencies; it is not shipped in the APK. The independent consumer decodes enum phase kinds and TimeSpan durations into named phases and exact ticks, validates actual/main/split/coverage conservation, and interprets frozen targets/zones without today's defaults. It returns explicit unknowns for unsupported legacy facts and never derives a new final mean from raw data. A consumer must reject unsupported versions/units and malformed current facts rather than guessing.

The Android journal materializes all tables in one explicit transaction, then projects the detached snapshot without writes. No outbox status changes or Health Connect calls occur. Snapshot consistency is a storage transaction, not a fabricated common callback watermark: legacy GPS raw inserts may precede their derived checkpoint. New service-owned retry batches commit GPS, provenance, events and checkpoint atomically; older observations may still legitimately lead the last checkpoint. Preserve that raw row and the unchanged derived observation separately; never recompute the checkpoint to hide the difference. HR raw and its checkpoint are already atomic. A dedicated DEBUG ranchu emulator can request `loop-export-json-run` with an existing synthetic UUID; the file is saved only in the app's private files directory. This hook deliberately uses the explicit version-1 diagnostic projection, not the normal version-2 share-file path. It runs the detached journal reader on a worker so ordinary service callbacks can continue during snapshot validation; it captures only the application directory and no Activity. The hook is absent from Release, adds no screen and never creates a run. Target only the coordinated emulator serial. Normal disclosed Android sharing is now delivered separately through the version-2 path described above; its chooser return does not prove recipient delivery. The original foundation did not provide that UI. Normal Health Connect activation/provider delivery and physical WHOOP outcomes are not established by JSON projection or sharing.

## Ghost version 3 · candidate, native acceptance pending

[run-v3.schema.json](run-v3.schema.json) and [sample-ghost-v3.json](sample-ghost-v3.json) define the separate activityKind=ghost envelope. The example is an explicitly ended positive incomplete synthetic race, with a full embedded frozen previous comparison, unknown current position and raw receipt facts; it is neither an actual session nor a Verified result. Read the [owning eligibility/disclosure/semantic-validation contract](../../knowledge/integrations-data.md#ghost-ai-json-v3-contract). Its original checkpoint stays PascalCase/checkpoint1, including frozen nullable facts. Normal Core2 and explicit diagnostic1 are unchanged. The candidate includes the v3 projector, an independent semantic parser branch and the existing Android disclosure/share integration. Typed marker-only local saved-part confirmation gates interrupted Ghost. Actual native chooser/recovery/focus/file lifecycle and merge remain pending. Schema shape validation cannot establish cross-field clock/identity equality or physical truth.
