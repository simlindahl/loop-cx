---
name: spec-change
description: Använd när ett krav, flöde eller en design för löparappen ändras.
---
1. Läs AGENTS.md och aktuellt avsnitt i knowledge/product.md. Följ statusflödet i AGENTS.md: flytta ärendet till Doing innan arbetet börjar och verifiera genom återläsning. Beskriv användarens konkreta situation och önskat resultat i en GitHub-issue.
2. Ändra den kanoniska OKF-sidan. Lägg till ett observerbart acceptansexempel och länka från issuen. Bevara YAML-frontmatter med type och relativa länkar.
3. Uppdatera berörda mockuper. Vid ändrat gränssnitt dokumentera vilket underlag Simon har godkänt i design/decision.md. Ett utkast eller ett agentomdöme är inte ett godkännande.
4. När nästa steg kräver Simons input eller designgodkännande: färdigställ oberoende arbete, flytta till Waiting och ange beslutet som behövs med länkat underlag. Efter svar, följ återgångs- och slutreglerna i AGENTS.md. Verifiera statusbytet; rapportera konkret fel om det misslyckas.
5. Dela arbetet i minsta byggbara ändring. Lägg issuen i GitHub Projects, länka PR och redovisa avvikelser mot beslutat krav.
