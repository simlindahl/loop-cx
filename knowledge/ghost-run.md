# Ghost Run

[Product entry point and ownership](product.md). M1 requirements unless explicitly marked otherwise.

## Ghost Run

<a id="omfattning-och-ingång"></a>
### Scope and entry point

Ghost Run is a separate feature, accessible from Training without changing the existing three main navigation destinations. After a completed continuous workout, the runner can choose Save route to Ghost Run in session details. This applies only to main-set distance, not warm-up/cool-down. Intervals, pacers/target pace and arbitrary previous attempts are excluded. Ghost Run uses English, Basalt, Space Grotesk and Material Icons. Use the [approved twenty-one-state reference](../design/mockups/ghost-run/index.html#ghost-routes) under its [decision and limits](../design/decision.md#ghost-layout-approval); the matching older gallery examples are historical context.

<a id="race-identity-and-applicability"></a>
#### Race identity and applicability

Ghost Run is a competitive activity separate from Core/Cx conditioning. Starting, executing, displaying, recording and exporting a race must identify Ghost Run, its route/version and frozen reference/race rules. Do not use C2/Zone 2, an easy-run purpose, RPE 4 or a Core template revision as race identity. RPE and optional pace/HR-zone targets are not applicable: neither ask for nor display them. Represent that explicitly as null/absent under the versioned contract, never RPE 0 or a fabricated C2 template. Measured pace/HR remain valid measurements, distinct from training targets.

A race can use a route captured from C2 without becoming C2. The source remains a completed continuous workout's contiguous main route only; intervals, imported tracks, automatic route detection and arbitrary builders are not added. Preserve source warm-up/cool-down exclusion, original metadata and raw data. Shared timing, recording or training-active accounting does not transfer a Core classification to the race. The existing race-clock, pause, route/reference and quality rules below remain unchanged; this product decision does not approve revised detailed Ghost layouts or release the reader runtime hold.

<a id="spara-och-välja-rutt"></a>
### Save and select a route

Save a named route with stable ID, version ID, ordered geometry, fixed start, finish and direction, and the source session's main phase. Review GPS evidence before saving; a significant gap must not become an invented continuous route. Show an understandable reason if the route cannot be saved. The source session becomes the first comparison reference if the full attempt can be verified. Creating the route does not change raw data or the original session.

Require the same route version, start, finish and direction. Changed geometry creates a new version and is not automatically compared with old records. Equal distance alone is insufficient. Arbitrary start points, reverse direction, multiple laps, a route editor, import and automatic route detection across all history are outside the first version. A loop or out-and-back route must not finish on an early pass near the finish.

<a id="motståndare-och-årsurval"></a>
### Opponent and year selection

Offer Year best and Personal best. Year best is the lowest verified elapsed main-set time among eligible attempts that started in the current calendar year. Use the attempt's stored local start date and time zone; later time-zone changes must not move dates. For a new start, determine the current year from local time and freeze it at start. Personal best is the lowest verified elapsed main-set time ever on the same route version. Break ties deterministically, for example by earliest start and then session ID.

Show when the same attempt holds both records. Without a year best, offer Set first time without a ghost or personal best if available. Without either record, let the runner set a first time without a ghost. Freeze the reference session, route version, record time and comparison rules at start; never change the ghost mid-session. A new valid result updates applicable records only after finishing and final storage. Never count the same recording twice.

<a id="start-tävlingsklocka-och-paus"></a>
### Start, race clock and pause

Starting requires a sufficiently reliable position near the correct start. Show Move to the start or GPS uncertain when the start cannot be verified. Start Ghost Run resets the race clock and starts runner and ghost together. Any warm-up precedes this start; cool-down follows the finish.

The route finish determines the end of the Ghost Run main set and replaces ordinary time/distance targets. Use monotonic elapsed time from main-set start to verified finish crossing. All stops, manual pauses and autopause count in race time. Show Race time keeps running during stops and pauses before starting.

Pause training pauses ordinary active training counters and coaching under the base rules, but does not pause the race clock, ghost or GPS recording required for route verification. Save these positions separately as race evidence; do not add paused distance to ordinary active counters. Do not automatically resume training after a manual pause. Playback preserves standstill and pause time. A pause alone never disqualifies a record.

This is an explicit Ghost Run exception to the base specification's frozen active measurements during pause. A verified finish crossing must be able to finish the race even while main-set training is paused. End attempt saves an incomplete recording without a record. Process death must not create a verified result by filling missing distance or time; preserve the recorded part with an interruption marker.

<a id="uppspelning-och-jämförelse"></a>
### Playback and comparison

Save raw coordinates, measurement time, accuracy, UTC, monotonic/relative elapsed time, phases, pauses, data gaps and quality status. Derive ordered route position s(t) for the current and reference attempts. Use the same versioned geometry and documented calculation rule for both; do not silently change old results when filters change. Reference time is elapsed time including stops, and the ghost follows recorded pace variations. Interpolate only between sufficiently close valid points; large gaps mean unknown evidence.

Metres ahead = runner route position minus ghost route position at the same race time. Seconds ahead = reference arrival time at the runner's current route position minus current race time. Positive means ahead. Arrival time is the first verified arrival in the correct sequence, even when the reference stands still there. Do not use straight-line distance or metres divided by current pace for the time difference. Keep recorded running distance separate from progress along the route.

Match a plausible sequence of route segments using previous position, feasible movement, direction and GPS quality. The nearest point on the whole route is insufficient at crossings, parallel sections and turnarounds. No shortcut may create a false lead or record. Display rounded metres/seconds and approximate or unknown comparisons when quality requires it. After the ghost finishes, its marker stays there while the race clock and time comparison continue until the runner finishes. Freeze the final result at the runner's verified finish crossing.

<a id="giltighet-och-osäkerhet"></a>
### Validity and uncertainty

A record requires the correct start/finish, the complete route in order and enough evidence to exclude a significant shortcut or wrong direction. GPS loss means unknown position, not standstill. With uncertain GPS or clear route deviation, the clock and ghost continue but comparison values are hidden. Restore them only when the correct position is reliable again. Re-entry may restore the training comparison but does not itself prove a skipped section was completed. Pauses or a brief deviation do not automatically exclude a record if the entire route can still be verified.

Save incomplete or insufficiently verified attempts with a concrete reason and do not update records. A small data gap does not automatically disqualify, but must not hide a possible shortcut. Do not fix universal thresholds before testing: document and test start/finish tolerance, route corridor, persistent deviation, gap length and update frequency using synthetic tracks and a physical Pixel.

<a id="livekarta-ljud-och-låst-skärm"></a>
### Live map, audio and locked screen

Show an ordered route line with direction/start/finish, a solid accent runner marker and a slightly transparent white ghost with a dark outline. Shape and text complement color; both markers must remain distinguishable when overlapping. Time difference is primary; approximate distance in metres is secondary. Follow the runner with recentering and an optional route overview. A distant opponent must not force an unreadable zoom level. Show map status separately from GPS status.

Give short deviation announcements and optional spoken comparisons, coordinated with the ordinary audio queue and without stale announcements. The first version covers the route line, direction and deviation announcements, not turn-by-turn navigation or rerouting. The Android service owns the race clock, GPS, playback and comparison. Blazor/map and notification consume the same state; separate UI timers must not determine results. The lock-screen notification shows race time and comparison where Android allows, plus Pause training/Resume training. Its text is projected only from the current service Ghost snapshot: race elapsed in the title, nullable time difference as the primary comparison and approximate along-route metres as secondary expanded text when known. Positive differences say ahead, negative differences behind using absolute values, and an exact zero says Level. No opponent says No ghost · setting a first time; an existing opponent with unavailable comparison says Comparison unavailable with the current GPS/off-route status, never a held old gap or a pace-derived distance. Training pause explicitly says the race clock continues. Storage failure overrides collapsed comparison, distinguishing a live recording failure from an unconfirmed final save; pending terminal commit is Saving recording and only a confirmed save is Saved locally. Reuse the ordinary collapsed/BigText notification pattern and owner-bound tap/Pause/Resume actions, with no new timer, freshness rule or custom layout. The bounded emulator delivery evidence below does not establish physical lock-screen visibility. Verify exact system layout on the phone.

Independent QA approved bounded API35 notification-shade delivery using actual source `74ae946` and APK SHA256 `e0dd1ca1d79b25126c4a7bf8ccd753d4993012132a4ba02fd4fd21aa7fca3ebf`. They exercised no opponent, supported comparison and unavailable comparison without stale values; same-owner Pause/Resume with advancing race elapsed; live/final save failure and explicit Retry to confirmed Saved/reference. Normal and Android 200% presentation received bounded UX approval. Transient Saving and the retired Saved notification were not captured; confirmed local Saved/reference was observed in the app, while transitional copy retains source/host scope. Ahead/Level/off-route matrix and genuine TalkBack are not claimed as native observations. The first actual terminal notification tap opened the same run ID; a second tap from a History title was inconclusive. Keyguard did not show Ghost, so lock-screen visibility remains unproven under the unchanged Low/Public notification configuration and OS policy. This is neither phone acceptance nor full Ghost/M1 completion. Original observer failures retain their diagnostic scope; no missing observation is converted into a pass.


Load route and reference data locally before starting; no new server is needed. Recording and comparison must work without a network/map key. An offline background map is not guaranteed; show the route geometry and markers as a simple overview when the background is unavailable. Stop rendering/animation when the map is hidden and restore the same session on reopening. Measure energy use for ordinary recording, Ghost Run with the screen off and a visible map under comparable Pixel/WHOOP/Spotify conditions.

### Stored continuous source bridge · version 2

The next integrated delivery starts at a durably Saved continuous C2 run, through Save route to Ghost Run and the stored route catalogue/detail, then the real service-owned race path. Frozen source template/protocol/category and applied phase facts establish eligibility, never current Settings or a guessed legacy workout type. Intervals, unfinished recordings, unknown source classification, missing clock/local-zone provenance or insufficient route geometry have concrete save-blocking reasons. The approved route/reference/detail/start actions must lead to real operations; no fake/disabled race start, Core/RPE race sentinel or substitute prototype is a delivered flow. The feature stays draft until that service path is connected.

A stored-source bridge has its own explicit version2. Geometry still derives from actual supported main-route evidence under one frozen technical capture policy; the full source attempt uses effective Main start/end elapsed, including pauses and unobserved tails. Progress is relative to that actual Main start, not normalized to the first GPS receipt. The historical first/last-GPS ObservedSpan contract remains version1 and is not silently reinterpreted. Preserve all source callbacks in their original stored order with raw coordinates/clocks/accuracy and available assessment/continuity provenance. A versioned derivation may exclude an explicitly ignored duplicate from geometry, but never remove/reorder it in archived source evidence. History's filtered StoredRoute/map links do not supply the complete raw evidence and are not Ghost verification.

A trailing raw callback explicitly recorded as not-assessed/Finalization after the callback clock crossed Main end may be retained without discarding the supported earlier geometry. Its measured time at or just before Main end is not assessed endpoint evidence: retain the raw row and full Main elapsed with an unknown suffix and an insufficient-evidence reason, not PB/year-best. This exception cannot hide interior rejected/unassessed points or a valid point after that terminal suffix.

Unknown prefix/suffix or unsupported internal coverage remains explicitly unknown, including unknown progress endpoints when needed; do not fill it with invented known zero/finish samples. A source attempt enters PB/year-best only when a positive complete policy-supported evaluation establishes start/finish/ordered-route evidence with supported known start/finish spanning its full elapsed window. Unknown internal comparison intervals do not automatically exclude a record when the frozen policy can still prove the complete ordered route; no universal All(points.Known) gate is introduced. Persistence alone does not assign Verified. The frozen pilot policy is an algorithmic eligibility rule, not field validation of universal accuracy thresholds; physical acceptance stays open without permanently disabling otherwise proven algorithmic cases.

Use recorded UTC/boot Main-boundary provenance. Freeze the source attempt's Main-start civil time using its saved source zone/offset evidence; derived values identify that provenance rather than claiming a later OS zone was observed at Main start. Missing/unresolvable/conflicting source zone evidence is not replaced with current timezone or UTC. Original C2 recording, AI/HC payloads, aggregates and source prescriptions remain immutable. Google SDK/data-flow approval is still pending and is not implied by this local bridge.

### Native archive adapter boundary

The isolated archive adapter uses the existing local session database and the canonical [archive DDL](../storage/ghost/schema-1.sql), with an independent archive revision marker and no session-schema version change. It installs atomically only when explicitly used. Save a captured route/version and its source attempt together; identical stable identities/evidence are idempotent, conflicting copies roll back without replacing archived rows. Readers return the frozen geometry, rule/quality policy, raw/progress evidence and saved local start/zone for existing domain selection. Successful storage is never proof of Verified quality; unsupported legacy zone provenance is not backfilled. See [the native archive contract](../docs/ghost-archive.md).

Acceptance for this bounded slice is real Android SQLite initialization, route/source-attempt rollback, identical/conflicting retries, reopen and preservation of existing run/raw/outbox data. The session database version remains unchanged; an unknown/partial Ghost namespace is rejected. No route-save screen, race-service integration, UI prototype, map provider or health operation is delivered by this adapter.

### Service-owned race checkpoint · version 1

A Ghost race is an explicit `ActivityKind = "ghost"` branch of the same RunService and single active run identity. Its version1 checkpoint contains frozen route/version/name, reference/mode/year, comparison and matching policy, race start UTC/local-zone/boot anchor, the race clock and training pause intervals, ordered matcher/progress state and raw evidence. Core phase/remaining-time/template fields are not applicable and remain null; no artificial C2, TimedPhase, RPE or timer represents a route race. The existing source bridge v2 and archive schema1 stay distinct. Existing checkpoints without the discriminator remain Core under their unchanged version1 contract.

A foreground-service start request first receives a temporary, honestly labelled checking notification before journal/archive/JSON/GPS/model preparation or any rejection callback. Cold service creation must not open the journal before this bootstrap. This notification is not an accepted race, run ID, clock, sensor or saved start. If an owner already exists, reject the competing request without replacing its notification or stopping it. Pre-accept rejection/cancellation removes only the temporary foreground state and retires that unowned start using its Android start ID before completing/notifying the UI; the single acceptance boundary and established owner/Retry invariants remain unchanged.

Before a race clock or ownership is committed, the service validates a currently fresh actual position against the frozen matching policy and correct start gate. Readiness failure creates no race/journal/record. The race clock uses absolute boot monotonic time; matcher/playback/progress use elapsed time relative to this actual race start. The service handles race GPS before any Core manual-pause early return. Stops, manual/automatic training pause and gaps never stop or rewind race elapsed, ghost playback or raw race GPS. Base autopause removes only its exact ten-second retrospective training interval and retains the later active tail; it must not subtract the whole callback delay or retroactively move the race start/end. A verified finish uses the matcher's measured crossing time, clipped once even if received after a newer tick; finish during pause remains possible. End attempt is explicitly incomplete. Process death preserves only the last committed interrupted prefix, never reconstructing a running clock or Verified finish.

At the actual validated Ghost start, freeze the current HealthConnectConsentRevision and its export intent in the typed Ghost checkpoint and the same start transaction, using the existing prospective start-consent owner. Preflight or opening a route is not start and freezes no consent. ON at start retains the actual revision through the source-bound Ghost mapping/queue integration; OFF at start stores null/no intent and later settings or mapping cannot backfill it. Unavailable or unsupported mapping remains a separate local disposition, not permanent pre-consent or an ACK. The separate Ghost mapper/queue uses these frozen facts plus current permissions and the other existing export gates, preserving normal DEBUG provider-write blocks. Result copy distinguishes local save, pending, action required, disabled synthetic and confirmed export; only a complete source-bound provider acknowledgement confirms export. History reuses the existing secondary Retry action and returns focus to the stable heading after explicit Retry, without background-refresh autofocus.

The ordinary runs/raw/event/save-buffer boundary persists Ghost with `OriginalPlan = []` explicitly not applicable and its own checkpoint version. Start checkpoint and frozen ghost_race_starts row commit together; terminal checkpoint/raw/events and archive attempt commit together on the same SQLite connection/transaction. Only successful EndTransaction acknowledges saved. Transient write failure retries the identical frozen ID/revision/start/reference/end/evidence, including uncertain local commit return; structural/open/read failures stay nonretryable with bytes preserved. No asynchronous remote callback exists in this local boundary. No second independent archive commit may acknowledge a terminal result.

Readers dispatch on activity kind before Core History/recovery/route/export/HC interpretation. A Ghost result is not a Core completed plan. Its stored detail uses its actual route, elapsed/training time, reference and quality/reason, with local Saved distinct from export. Current Core AI v1/v2, schemas, diagnostics, HC records/payload/hash and queue attempts stay byte/semantically unchanged. Until explicit Ghost export mapping exists, no Core automatic export queue entry or ACK is fabricated; the UI reports local-only export unsupported. Normal Ghost JSON sharing uses its explicit AI v3 activity discriminator/schema/parser, delivered separately in PR114 while preserving Core v1/v2; the service checkpoint alone is not export evidence.

Observable source acceptance includes fresh near-start failure with no race creation; one actual start identity/reference through navigation/notifications; manual/automatic pauses while GPS and race elapsed continue; exact retrospective training exclusion and delayed active tail; finish during pause and delayed finish clipping; explicit End/incomplete; atomic start/final rollback, stable frozen retry/uncertain return and cold interrupted prefix; kind dispatch before all Core consumers. Algorithmic positive matching under a versioned pilot is not physical route/sensor/audio calibration. Merged [PR113](https://github.com/simlindahl/loop-cx/pull/113) connects actual Start→race GPS→finish/End→stored Ghost detail with bounded native acceptance. Remaining audio, physical lock-screen notification acceptance, Ghost HC mapping, Google background integration and other physical acceptance are not removed from the whole issue.

The only zero-duration exception is an explicit End resulting in Incomplete with race elapsed exactly zero in the recorded monotonic clock. Freeze the typed `ArchiveDisposition = "zero-elapsed-incomplete"`, exact zero and reason in the terminal checkpoint; commit that journal/raw/event prefix and its frozen race-start row together, without a GhostAttempt or record. Do not fabricate one millisecond or mutate archive schema1, whose attempt contract requires positive elapsed. All positive-duration terminals retain the ordinary same-transaction archive-attempt requirement. A zero-duration Finished result or any other missing-attempt disposition is invalid. Retry/rollback/idempotence retain the exact zero checkpoint/start, and cold History reads the incomplete local result directly without Core fallback or an invented archive attempt; PB/year-best remains unchanged.
