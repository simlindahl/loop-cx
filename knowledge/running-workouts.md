# Running workouts

[Product entry point and ownership](product.md). M1 requirements unless explicitly marked otherwise.

<a id="produkt-och-leverans"></a>
## Product and delivery
An English-language running app for a runner who rotates between a few favourite workouts. After initial setup, a saved workout must start from the home screen with one tap. The same recording must work with the screen visible, Spotify in the foreground and the phone locked. Deliver an Android app, an installable APK for private use, reproducible Windows instructions and a verification report. The first target phone is a Pixel with a WHOOP band. No server is needed. Private APK distribution is the proposed default.

The app's own screens, controls, accessible names, errors, notifications and voice coaching use English in v1. Feature names in this specification describe functionality. Preserve the user's own workout names. Android controls the language of system-owned dialogs.

## LOOP Core
LOOP Cx is the running app for C1 and C2. The approved Core-first family and flows below govern the next implementation: C1 SIT/HIIT/threshold variants share global 4/3 warm-up and cool-down defaults, and C2 has target RPE 4 with no warm-up and cool-down. Preserve source/category/template revision and the actual resolved plan with every execution; a shortcut does not become an arbitrary workout builder. Support for complete racing plugins remains separate M3 work.

Core C1/C2 RPE and optional training-target rules do not classify a [Ghost Run race](ghost-run.md#race-identity-and-applicability). A race may reuse timing, GPS, HR, journal and training-active bookkeeping, but has its own activity identity with no RPE or optional pace/zone target. A shared phase engine must expose a typed not-applicable/race seam rather than a sentinel integer or changed meaning for historical Core phases.

**Frozen compatibility:** C1 revision 1 retains its original 10/5 warm-up and cool-down and 38-minute total; C1 revision 2 retains five 3-minute work efforts, four 2-minute recoveries and 8/4 warm-up and cool-down (35 total / 23 main). C2 revision 1 retains 45 minutes at target RPE 3. New Core-first starts resolve C1 family revision 3 with an official protocol ID/revision, or C2 revision 2 at target RPE 4. They freeze the actual plan, targets, source and shortcut identity; no earlier recording is relabelled or rewritten. Zone 2 is target intent, never evidence of measured zone monitoring without valid sensor data.

## Workouts and statistics

The [approved Core-first decision](../design/decision.md#core-first-approved-variants) supersedes the arbitrary workout builder and former warm-up/cool-down proposals. New C1 family defaults are 4/3, with the global independent opt-outs described below. C2 has no warm-up or cool-down. These rules do not establish completion of every history, sensor, export or physical acceptance requirement.

1. Core-first C2 uses a 20–120-minute duration slider in five-minute steps, default 45. It has no warm-up and cool-down. Automatically split at each full kilometre of the main set and retain the final incomplete split with its actual measured distance. The old generic time/distance/manual-end builder is not part of this Core-first scope; separate Ghost/M3 requirements retain their own owners.
2. C1 uses one of the three official timed protocols below, with user-selected integer N work efforts and N−1 recoveries. Work/recovery lengths and RPE stay fixed per protocol. The planned main set, INCLUDING recoveries and EXCLUDING warm-up and cool-down, must be 10–60 minutes: N × work + (N−1) × recovery. This permits SIT 4–18 reps (default 7), HIIT 3–12 (default 5) and threshold 2–7 (default 3). Do not silently reinterpret the limit as sprint/work-only minutes or force an exact ten-minute minimum when whole repetitions produce a higher smallest valid dose. Save the actual count/plan with each execution and shortcut. Further free units/phase editing remain outside the bounded scope. The engine's generic N=1/no-recovery invariant does not create a valid Core dose under these limits.
3. Target RPE is predefined and read-only: C1.1 10/2, C1.2 7/3, C1.3 6/3 (work/recovery); C2 4. It is intended effort, never a measured result. The bounded additional target editor offers pace in min/km OR a heart-rate zone for work and optional recovery in that mode. Missing sensor/zone data cannot make an intended target into a measurement. A nearby accessible information button explains RPE.
4. All C1 variants default to four minutes progressive warm-up and three minutes easy cool-down. Each global warm-up and cool-down phase may independently be Off (0, omitted from the resolved plan) or 1–15 whole minutes; fractional, negative and larger durations are invalid. These are global Settings only, never per-run switches. The pair is overridden by the one global Settings pair at the next start, including existing shortcuts. Resolve and freeze the actual plan; no per-run or per-favourite warm-up and cool-down switches/editor. C2 never inherits warm-up and cool-down. During warm-up and cool-down, separate +1 min taps and volume up in the training view add 60 seconds each; Start main set and Finish and save retain their respective runtime skip/finish behaviour. These actions do not silently change Settings or rewrite the saved shortcut. Preserve already recorded data. This supersedes the earlier generic independent warm-up and cool-down switches and 3/2/B proposals.
5. The whole run includes warm-up, work, recovery and cool-down. The main set includes work and planned recovery. Save both elapsed and active time. Average pace is active time divided by distance; average heart rate is a time-weighted mean of valid readings. Report gaps as unknown time. Never divide by zero. Calculate zone statistics with the boundaries frozen at start.
6. Autopause after ten seconds of reliably observed standstill and resume automatically on movement. Simon explicitly approved this confirmation window and retrospective backdating on 13 November 2026: subtract the full ten confirmed seconds from active training time rather than starting the pause only at detection. Exclude the entire recovery phase. During timed recovery, standing still counts in full. During distance recovery, timing continues while remaining distance awaits movement. Manual pause takes precedence over automation and requires manual resume. Freeze active time, recorded distance, phase countdown and coaching during pause. All ten seconds must fit within one eligible phase: a phase transition, recovery or finish cancels the candidate and never reopens a completed session. Explicit manual pause cancels it; manual resume begins a fresh eligible window. A real +1-minute extension preserves motion evidence and its command log; duplicate commands do not change the window. This supersedes the earlier five-second/detection-only proposal; immutable raw observations remain unchanged. Lost GPS means unknown movement, not standstill.

   Timed C1/C2 implementation contract: identify the eligible phase by instance/index, not only its kind. The confirmation window is fixed at the first reliable standstill observation plus exactly ten measurement seconds. For onset 0, confirming sample 10.5 and processing receipt 12, exclude only [0,10]; retain [10,12] as active time with explicit unknown quality where unsupported. Record onset, excluded-through, confirming-sample and processing/detected times separately as absolute boot-monotonic times, with the frozen run-start monotonic anchor in motion state. Existing elapsed_ms remains session-relative. Enter automatic pause at receipt 12; do not infer additional standstill from delivery delay. A phase/finish/manual-pause boundary already processed takes precedence over a delayed sample, even if that sample was measured before the boundary. Automatic resume takes effect at processing receipt of reliable movement, re-anchoring distance without charging paused displacement or inventing an earlier movement interval. Unknown observations while automatically paused neither resume nor accumulate training distance. Explicit Pause during automatic pause promotes it to manual pause; only explicit Resume releases that manual state.

   Any accepted moving distance edge after the onset cancels the candidate before confirmation, even if opposite endpoints both lie inside the stationary cluster. Keep the bounded candidate's derived distance/split contributions provisional. Confirmation removes only the fixed ten-second interval from phase/total/main active time and countdown; preserve actual plan extensions and command/event order. Retain any post-window active-time tail, without interpolated unsupported distance. Corrected derived checkpoint and the automatic event commit together; original plan, raw fixes and user commands are immutable. Existing observed elapsed/persistence columns keep their meaning. No new database schema or arbitrary workout builder is required.

7. Filter implausible GPS jumps. Mark interruptions in the map track and do not extrapolate lost distance. During a distance-based phase with lost GPS, active time continues and the phase waits for measurable distance. Document and field-test thresholds for movement, resume, GPS quality and live-pace smoothing.

## Audio configuration and coaching

One global audio standard applies to direct Core starts and seeds newly saved shortcuts. The default is a periodic summary every five active main-set minutes. A new shortcut copies its effective audio setting and thereafter owns its explicit saved value. An existing shortcut without audio metadata uses current global audio at each new start until an explicit shortcut value is saved; absence is not an explicit choice. Do not rewrite existing shortcuts or history. Freeze the effective audio configuration with every run. Shortcut audio editing never changes global defaults and needs no Standard/Custom mode switch.

The runner may select a custom positive time interval (minutes and seconds) OR distance interval in metres, independently of kilometre splits. Count from main-set start using main active time including planned Recovery, or accepted main distance. Warm-up, cool-down and pauses contribute nothing. Work↔Recovery does not restart the counter. Apply exact approved autopause corrections to derived counters without replaying already spoken announcements. Do not queue missed summaries across pauses/gaps; consume a threshold at most once. A higher-priority phase message may replace a due summary rather than leave stale backlog.

Announce Core phase transitions and target RPE. No new audio enable/mode switch is added. Priority is phase/RPE, current coaching, then current summary, with no overlapping or stale queue. All speech is English. Losing audio focus must not block the timer, recording or controls; never restart music the user stopped. Actual TTS, audio-focus, Spotify and locked-screen acceptance remains required.

Coaching uses current quality-supported smoothed live pace in seconds/km and fresh valid HR against the frozen personal zones. A pace deviation greater than 10 percent or HR outside the selected target zone must persist for 30 consecutive active seconds within the same split. At 5:00 min/km the boundaries are 4:30 and 5:30; exactly 10 percent is not greater than 10 percent. Reset on a new split, pause, data gap or return within target. Changing the phase-specific target cannot pool confirmation across different phases/targets. Missing or stale input confirms no deviation. Give one announcement per continuous deviation. RPE alone provides phase announcements and ordinary summaries, not a measured target. Never instruct the runner to accelerate a short SIT effort to chase lagging low HR.

Audio settings do not change the approved global C1 warm-up/cool-down defaults or opt-outs, add them to C2, or rewrite a frozen session. These Core coaching rules do not add training targets/RPE to Ghost races; Ghost comparison/deviation audio retains its [owning rules](ghost-run.md#live-map-audio-and-locked-screen).

## C1 variant purposes and evidence

| Variant | Purpose to explain to the runner | Default planned dose | Warm-up / cool-down | Main / total |
|---|---|---|---|---|
| C1.1 · Sprint intervals (SIT) | Train repeated maximal sprint efforts with substantial easy recovery. Sprint-specific effort is the defining stimulus; aerobic performance can also improve. This is a maximal-effort option, not the default progression for an inexperienced runner. | 7 × 30 s maximal work, 6 × 3 min easy recovery | 4 min / 3 min | 21:30 / 28:30 min |
| C1.2 · Aerobic intervals (HIIT) | Develop aerobic power through sustained, controlled hard intervals: the variant with the clearest VO₂max-oriented intent. ### Research basis and transfer limits

- **C1.1:** [Macpherson et al., 2011](https://pubmed.ncbi.nlm.nih.gov/20473222/) compared six weeks of running SIT against endurance training in young adults, with 10 participants per group. The SIT protocol used four to six 30-second all-out efforts on a manually driven treadmill with four-minute recoveries. Running aerobic performance improved without an increase in maximal cardiac output. This supports a running SIT purpose with long recovery, not a universal prescription or a claim that sprinting uniquely improves VO₂max. LOOP's default seven efforts, three-minute recoveries and warm-up and cool-down lengths are programming choices that differ from that study; outdoor running, other ages/experience and the complete Core rotation were not validated by this study. Maximal running requires appropriate familiarity, progressive warm-up and cool-down and safe conditions; shorten or stop rather than force a sprint when control is lost. Do not offer SIT as an automatic escalation for a runner returning from a layoff.
- **C1.2:** [Hov et al., 2023](https://pubmed.ncbi.nlm.nih.gov/36314990/) randomised 48 well-trained men to eight weeks of interval training. Four 4-minute aerobic efforts improved VO₂max more than the tested sprint formats. This supports the aerobic-power intent of sustained hard intervals; it does not directly validate LOOP's five 3-minute efforts, recovery, RPE, mixed Core rotation or expected individual improvement.
- **C1.3:** [Henritze et al., 1985](https://pubmed.ncbi.nlm.nih.gov/4018061/) compared training at and above an individually assessed lactate threshold with control in 33 college women using cycling. Threshold-related outcomes changed, with different results at and above threshold. This supports threshold-related capacity as a trainable concept, not the superiority or exact efficacy of three 6-minute running efforts. The transfer to this protocol is a programming inference: longer controlled bouts provide practice sustaining the intended effort. RPE 6 and a six-minute duration do not establish an individual's physiological threshold.

The three formats overlap in their training effects; the purpose labels describe emphasis rather than separate physiological compartments. Exact counts, recovery, warm-up and cool-down and RPE are pragmatic programme choices. No cited study validates the complete LOOP prescription or establishes that these warm-up and cool-down lengths suit every runner; existing runtime extension/skip remains available.

Pilot values are 30 m maximum horizontal accuracy, 10 s maximum sample age/gap, 12 m/s speed ceiling and retained movement hysteresis of at least 3 m or the sum of endpoint accuracy radii. These are conservative synthetic-test hypotheses, not field-validated thresholds or a guarantee of physical accuracy. Raw observations remain immutable.

Use monotonic measurement timestamps. Ignore duplicate/out-of-order delivery without changing newer trusted state. Recovery contributes to main distance and preserves a continuous valid main-set edge; entering recovery alone is not a GPS gap. Warm-up and cool-down do not contribute to main distance. Preserve final partial distance and any final active-time tail, with unknown pace where data is missing or distance is zero. Checkpoints retain the policy, accepted-distance totals, split times and quality flags without rewriting original plans or adding invented distance. Retrospective autopause and measured coverage are delivered in their subsequent slices. ### Production heart-rate implementation contract

### Live pace technical pilot

Live pace is a service-owned recent estimate from the exact accepted movement edges of the existing ordinary GPS filter, not the cumulative average or a UI clock. Version 1 uses a trailing 10-second window, at least three supported seconds to acquire a value and at most three seconds of freshness from the last accepted edge end. These are uncalibrated engineering hypotheses, not a physical accuracy guarantee or approved coaching interpretation. Freeze actual policy values with each run's derived snapshot.

Compute supported seconds divided by accepted metres, times 1000. A continuous accepted edge can be linearly clipped at the window boundary; that interpolation is derived, not another raw measurement. An edge longer than the whole window cannot establish recent pace and resets live acquisition, while ordinary accepted distance remains unchanged. Valid stationary fixes do not refresh movement freshness. Missing, stale, zero-distance or acquiring pace is null, never zero or infinity.

Use the existing filter's quality outcome: invalid/jump/gap/provider loss resets the live chain; duplicate/out-of-order delivery adds nothing and does not destroy newer evidence. Manual/automatic pause and resume, warm-up/main/cool-down reanchors and finish reset the estimate. Planned Work/Recovery can keep a continuous main chain; a real +1-minute extension does not discard trusted movement. Confirmed exact-ten-second Auto correction clears/reacquires live pace without changing raw observations, receipt-tail active time or real commands. Strict aggregate pace and finalized main/split values keep their existing rules. Native GPS/service/snapshot/journal and physical calibration remain acceptance work; no new sensor source, permissions, framework or server is introduced.
