# Running workouts

[Product entry point and ownership](product.md). M1 requirements unless explicitly marked otherwise.

<a id="produkt-och-leverans"></a>
## Product and delivery
An English-language running app for a runner who rotates between a few favourite workouts. After initial setup, a saved workout must start from the home screen with one tap. The same recording must work with the screen visible, Spotify in the foreground and the phone locked. Deliver an Android app, an installable APK for private use, reproducible Windows instructions and a verification report. The first target phone is a Pixel with a WHOOP band. No server is needed. Private APK distribution is the proposed default.

The app's own screens, controls, accessible names, errors, notifications and voice coaching use English in v1. Feature names in this specification describe functionality. Preserve the user's own workout names. Android controls the language of system-owned dialogs.

## Workouts and statistics

The [approved Core-first decision](../design/decision.md#core-first-approved-variants) supersedes the arbitrary-workout builder and former preparation proposals. New C1 family defaults are4/3; delivered legacy C1v2 remains8/4 until the separately verified implementation. C2 has no preparation. The rules below describe the target product, not a claim that every flow is already delivered.

1. Core-first C2 uses a 20–120-minute duration slider in five-minute steps, default 45. It has no preparation. Automatically split at each full kilometre of the main set and retain the final incomplete split with its actual measured distance. The old generic time/distance/manual-end builder is not part of this Core-first scope; separate Ghost/M3 requirements retain their own owners.
2. C1 uses one of the three official timed protocols below, with user-selected integer N work efforts and N−1 recoveries. Work/recovery lengths and RPE stay fixed per protocol. The planned main set, INCLUDING recoveries and EXCLUDING preparation, must be 10–60 minutes: N × work + (N−1) × recovery. This permits SIT 4–14 reps (default 6), HIIT 3–12 (default 5) and threshold 2–7 (default 3). Do not silently reinterpret the limit as sprint/work-only minutes or force an exact ten-minute minimum when whole repetitions produce a higher smallest valid dose. Save the actual count/plan with each execution and shortcut. Further free units/phase editing remain outside the bounded scope. The engine's generic N=1/no-recovery invariant does not create a valid Core dose under these limits.
3. Target RPE is predefined and read-only: C1.1 10/2, C1.2 7/3, C1.3 6/3 (work/recovery); C2 4. It is intended effort, never a measured result. The bounded additional target editor offers pace in min/km OR a heart-rate zone for work and optional recovery in that mode. Missing sensor/zone data cannot make an intended target into a measurement. A nearby accessible information button explains RPE.
4. All C1 variants default to four minutes progressive warm-up and three minutes easy cool-down, overridden by the one global Settings pair at the next start, including existing shortcuts. Resolve and freeze the actual plan; no per-run or per-favourite preparation switches/editor. C2 never inherits preparation. During preparation, separate +1 min taps and volume up in the training view add 60 seconds each; Start main set and Finish and save retain their respective runtime skip/finish behaviour. These actions do not silently change Settings or rewrite the saved shortcut. Preserve already recorded data. This supersedes the earlier generic independent preparation switches and 3/2/B proposals.
5. The whole run includes warm-up, work, recovery and cool-down. The main set includes work and planned recovery. Save both elapsed and active time. Average pace is active time divided by distance; average heart rate is a time-weighted mean of valid readings. Report gaps as unknown time. Never divide by zero. Calculate zone statistics with the boundaries frozen at start.
6. Autopause after ten seconds of reliably observed standstill and resume automatically on movement. Simon explicitly approved this confirmation window and retrospective backdating on 13 November 2026: subtract the full ten confirmed seconds from active training time rather than starting the pause only at detection. Exclude the entire recovery phase. During timed recovery, standing still counts in full. During distance recovery, timing continues while remaining distance awaits movement. Manual pause takes precedence over automation and requires manual resume. Freeze active time, recorded distance, phase countdown and coaching during pause. All ten seconds must fit within one eligible phase: a phase transition, recovery or finish cancels the candidate and never reopens a completed session. Explicit manual pause cancels it; manual resume begins a fresh eligible window. A real +1-minute extension preserves motion evidence and its command log; duplicate commands do not change the window. This supersedes the earlier five-second/detection-only proposal; immutable raw observations remain unchanged. Lost GPS means unknown movement, not standstill.

   Timed C1/C2 implementation contract: identify the eligible phase by instance/index, not only its kind. The confirmation window is fixed at the first reliable standstill observation plus exactly ten measurement seconds. For onset 0, confirming sample 10.5 and processing receipt 12, exclude only [0,10]; retain [10,12] as active time with explicit unknown quality where unsupported. Record onset, excluded-through, confirming-sample and processing/detected times separately as absolute boot-monotonic times, with the frozen run-start monotonic anchor in motion state. Existing elapsed_ms remains session-relative. Enter automatic pause at receipt 12; do not infer additional standstill from delivery delay. A phase/finish/manual-pause boundary already processed takes precedence over a delayed sample, even if that sample was measured before the boundary. Automatic resume takes effect at processing receipt of reliable movement, re-anchoring distance without charging paused displacement or inventing an earlier movement interval. Unknown observations while automatically paused neither resume nor accumulate training distance. Explicit Pause during automatic pause promotes it to manual pause; only explicit Resume releases that manual state.

   Any accepted moving distance edge after the onset cancels the candidate before confirmation, even if opposite endpoints both lie inside the stationary cluster. Keep the bounded candidate's derived distance/split contributions provisional. Confirmation removes only the fixed ten-second interval from phase/total/main active time and countdown; preserve actual plan extensions and command/event order. Retain any post-window active-time tail, without interpolated unsupported distance. Corrected derived checkpoint and the automatic event commit together; original plan, raw fixes and user commands are immutable. Existing observed elapsed/persistence columns keep their meaning. No new database schema or arbitrary workout builder is required.

7. Filter implausible GPS jumps. Mark interruptions in the map track and do not extrapolate lost distance. During a distance-based phase with lost GPS, active time continues and the phase waits for measurable distance. Document and field-test thresholds for movement, resume, GPS quality and live-pace smoothing.

## Feedback during workouts
The runner selects speech at a custom positive time interval (minutes and seconds) or distance interval in metres. Read the four main-set values, the four current-split values, live pace and heart rate in English. Speech frequency and split length are independent. Announce phase transitions and target RPE. Give short phase announcements priority over longer summaries and avoid overlapping or stale announcements while music plays. The proposed default counts periodic summaries from main-set start using active time or main-set distance.

Give brief coaching for a pace deviation greater than 10 percent or heart rate outside the selected zone for 30 consecutive active seconds within the same split. The proposed interpretation uses smoothed live pace in seconds/km and valid current heart rate. At 5:00 min/km, the thresholds are 4:30 and 5:30. Reset deviation time on a new split, pause, data gap or return within target. Give one announcement per continuous deviation. RPE without a measurable target provides phase announcements and ordinary summaries.

An ongoing Android notification on the lock screen and in the notification shade shows phase, remaining time/distance, heart rate and pace within the available system space. Warm-up: +1 min and Start main set. Main set: Pause and, for an open-ended workout, Start cool-down or Finish and save. Recovery: Pause. Paused: Resume. Cool-down: +1 min and Finish and save. Tapping the notification opens the current view. Test actual visibility in collapsed and expanded states with lock-screen notifications allowed.

C1.1/C1.2/C1.3 identify protocols, not favourite revision numbers. Simon approved the fixed RPE values and associated dose proposal below. Runtime implementation and its revised design remain separate delivery work; this specification does not replace the delivered C1 revision 2 or rewrite recorded plans.

|---|---|---|---|---|
| C1.1 · Sprint intervals (SIT) | Train repeated maximal sprint efforts with substantial easy recovery. Sprint-specific effort is the defining stimulus; aerobic performance can also improve. This is a maximal-effort option, not the default progression for an inexperienced runner. | 6 × 30 s maximal work, 5 × 4 min easy recovery | 4 min / 3 min | 23 / 30 min |
| C1.2 · Aerobic intervals (HIIT) | Develop aerobic power through sustained, controlled hard intervals: the variant with the clearest VO₂max-oriented intent. ### Research basis and transfer limits

- **C1.1:** [Macpherson et al., 2011](https://pubmed.ncbi.nlm.nih.gov/20473222/) compared six weeks of running SIT against endurance training in young adults, with 10 participants per group. The SIT protocol used four to six 30-second all-out efforts on a manually driven treadmill with four-minute recoveries. Running aerobic performance improved without an increase in maximal cardiac output. This supports a running SIT purpose with long recovery, not a universal prescription or a claim that sprinting uniquely improves VO₂max. LOOP's six efforts and preparation lengths are programming choices; outdoor running, other ages/experience and the complete Core rotation were not validated by this study. Maximal running requires appropriate familiarity, progressive preparation and safe conditions; shorten or stop rather than force a sprint when control is lost. Do not offer SIT as an automatic escalation for a runner returning from a layoff.
- **C1.2:** [Hov et al., 2023](https://pubmed.ncbi.nlm.nih.gov/36314990/) randomised 48 well-trained men to eight weeks of interval training. Four 4-minute aerobic efforts improved VO₂max more than the tested sprint formats. This supports the aerobic-power intent of sustained hard intervals; it does not directly validate LOOP's five 3-minute efforts, recovery, RPE, mixed Core rotation or expected individual improvement.
- **C1.3:** [Henritze et al., 1985](https://pubmed.ncbi.nlm.nih.gov/4018061/) compared training at and above an individually assessed lactate threshold with control in 33 college women using cycling. Threshold-related outcomes changed, with different results at and above threshold. This supports threshold-related capacity as a trainable concept, not the superiority or exact efficacy of three 6-minute running efforts. The transfer to this protocol is a programming inference: longer controlled bouts provide practice sustaining the intended effort. RPE 6 and a six-minute duration do not establish an individual's physiological threshold.

The three formats overlap in their training effects; the purpose labels describe emphasis rather than separate physiological compartments. Exact counts, recovery, preparation and RPE are pragmatic programme choices. No cited study validates the complete LOOP prescription or establishes that these preparation lengths suit every runner; existing runtime extension/skip remains available.

### Observable acceptance before variant delivery

For every variant, show the short purpose, resolved work/recovery dose, fixed target RPE and exact main/total time before start. Preserve protocol ID/revision and actual resolved plan with each execution. Legacy C1 plans retain their original identity and dose; a new protocol label cannot make different frozen plans equivalent for comparison.

Simon explicitly chose distinct purposes over a universal high-zone requirement: more than 6–7 minutes in zones 4–5 is a follow-up aim, not a completion condition. C1.3 may meet its purpose with less high-zone time. Never auto-extend a session, raise its target or tell the runner to accelerate solely to fill zone minutes. Interpret measured time only with valid heart-rate coverage and personal boundaries frozen at start; missing readings remain unknown. Heart-rate zone time is not time at VO₂max. Do not silently substitute percentages of maximum heart rate for WHOOP's current [heart-rate-reserve zones](https://support.whoop.com/s/article/What-is-Max-Heart-Rate-and-How-Do-I-Adjust-It?language=en_US).

## Ordinary distance and split pilot

The first service-integrated distance slice accumulates only accepted ordinary GPS edges, separately for the whole run and main set (work plus recovery). Freeze a versioned technical filter policy per session. Pilot values are 30 m maximum horizontal accuracy, 10 s maximum sample age/gap, 12 m/s speed ceiling and retained movement hysteresis of at least 3 m or the sum of endpoint accuracy radii. These are conservative synthetic-test hypotheses, not field-validated thresholds or a guarantee of physical accuracy. Raw observations remain immutable.

Use monotonic measurement timestamps. Ignore duplicate/out-of-order delivery without changing newer trusted state. Reject invalid or excessively old fixes; break and re-anchor across genuinely rejected samples, missing GPS, manual pause and preparation/main/cool-down boundaries rather than allocating an ambiguous edge to the callback's current phase. Retain the movement anchor through small valid displacements so slow movement is not permanently discarded. Recovery contributes to main distance and preserves a continuous valid main-set edge; entering recovery alone is not a GPS gap. Preparation does not contribute to main distance. Split accepted main distance at each kilometre, interpolating active time within a continuous accepted edge. Preserve final partial distance and any final active-time tail, with unknown pace where data is missing or distance is zero. Checkpoints retain the policy, accepted-distance totals, split times and quality flags without rewriting original plans or adding invented distance. Distance-target phases and the approved retrospective autopause remain separate subsequent engine work; this pilot does not close #2 or physical calibration acceptance.

## Autopause technical pilot and acceptance

The first timed-engine slice uses a versioned local movement policy, frozen with the run. Proposed pilot limits are maximum 5 m horizontal accuracy, 3 s observation gap/age, a 2 m stationary cluster around the candidate origin, the frozen ordinary distance speed ceiling (12 m/s pilot) and movement confirmation beyond max(3 m, endpoint accuracy radii sum). These are synthetic-test parameters, not physically validated standstill or slow-jog guarantees. A cluster departure that is not yet trustworthy movement is Unknown and breaks the standstill candidate. Missing, poor, rejected, duplicate or out-of-order data cannot supply additional confirmation time. Continue collecting raw GPS while automatically paused; do not equate no accepted distance increment with standstill. Physical false-pause/slow-jog and resume calibration remain mandatory and NOT RUN.

Acceptance examples: 9.999 s cannot pause; ten reliable seconds in one eligible phase exclude exactly ten active seconds. Work 6 s plus Recovery 4 s cannot confirm; recovery counts normally. Repeated Work instances cannot share a candidate. A completed phase/run never reopens. A real +1 at candidate second 5 survives confirmation with its real timestamp; duplicates do not restart the window. Manual Pause at second 8 cancels it; movement cannot release Manual. Auto → explicit Pause → movement stays Manual. A quality gap starts a fresh window. Delayed confirmation uses the 0/10.5/12 contract above. Resume re-anchors without a relocation jump. Assert active/countdown/main/split conservation and actual GPS → service → atomic SQLite checkpoint/event/raw fixes with exports disabled; host tests alone are not native proof.

Simon separately confirmed that existing in-session C1 preparation +1 minute and skip actions remain supported; Settings seeds defaults rather than replacing those runtime controls. This does not approve a narrow or generic favourite editor: allowed Core personalization fields remain a separate owner decision under #3.
